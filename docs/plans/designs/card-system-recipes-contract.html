System contract / recipes

What the model is allowed to emit

Seven recipes cover the observed topic space. Each is a fixed, ordered block composition and one accent — the model chooses a recipe and fills it, it does not invent layouts. Everything below is expressible with the eight existing block kinds; no spec change is required.

Accent is a fill, never a caption

Accent may colour bars, area gradients, chart strokes, bullet dots, status dots, and text at ≥ 20px. Nothing else. #fb8500 has luminance 0.373 against a 0.808 glass — 2.03:1, which vanishes under 4:2:0.

Three accents, chosen by topic domain

Orange #fb8500 for business and system data (unchanged default), violet #6D28D9 for people and culture, teal #0F766E for science, history and comparison. Both additions are existing AVATAR_TINTS foreground values — no new hues enter the brand.

At most four blocks

A 358px card holds roughly 4 blocks before it exceeds a comfortable frame height. The engine should refuse to emit a fifth rather than let layoutCard run the card past the frame.

Every image recipe has a no-image twin

The renderer silently drops any image that fails or would taint the capture canvas. The block list must read as finished without it — which is why the fallback block is first, not last.

One emphasised metric, six glyphs

At most one emphasis: true per row, and its value must fit ~6 glyphs at 26/700 within a 3-up row. $240,000 does not; $240K does.

Source line when the claim is external

Any card built from a fetched fact ends with a single status_list row in info state naming the source and freshness. It is the cheapest credibility the format has.

Palette extension
Two additions, both already in the codebase as AVATAR_TINTS foregrounds: #6D28D9 (L 0.098) and #0F766E (L 0.142). Both are darker than #fb8500 (L 0.373), so they carry more luminance contrast, not less.
Contrast over bright glass
violet 5.81:1 · teal 4.47:1 · orange 2.03:1 against a 0.808-luminance glass.
Unchanged
Default theme, all four approved fixtures, all eight block kinds, and every token in tokens.ts except the two proposed additions.
